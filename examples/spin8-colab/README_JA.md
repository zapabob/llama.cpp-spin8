# Spin8 HF → Colab A100 → GGUF・ベンチマーク

2026-11-21 改訂。対象は `Qwen/Qwen3.8-27B` と、同じ `qwen3_5` 形式の対応チェックポイントです。

## 使い始める手順

1. `Spin8_A100_Weight_Edit.ipynb` をGoogle Colabで開きます。
2. 「ランタイム → ランタイムのタイプを変更」で **A100 GPU・ハイメモリ・最新（推奨）** を選びます。
3. 通常のSpin8量子化なら、最初の設定セルを変更せず、上から実行します。
4. 環境準備、小型モデルでの実機確認、HFダウンロード、直接量子化、完成モデルでの推論確認、GSM8K評価が順番に進みます。
5. 完成品を残す場合は最後のDrive保存セル、またはHFアップロードセルを有効にします。

必要な実装・パッチ・小型検証モデルをノートブックに埋め込んであります。追加ZIP、手動で変換した元GGUF、数学ドナーの手動ダウンロードは不要です。公開されている元モデルのダウンロードにはHFトークンも不要です。

HFへのアップロードには、最初のセルの `HF_REPO` と、Colabシークレットの `HF_TOKEN` が必要です。初期設定は非公開リポジトリです。トークンをノートブックのソースへ貼り付けないでください。

## 通常量子化・数学差分・方向除去

初期設定は通常のSpin8量子化です。数学ドナーや方向ベクトルがなくても、この経路が動きます。

数学差分は `MATH_DELTA=True` で有効にします。同じ祖先からの数学ドナーを使い、対象行列を次の式で直接変更します。

`W_edited = W_source + alpha * (W_donor - W_source)`

既定の `alpha` は0.25です。このノートブックで回答データによるSFT・QLoRA・勾配学習は行いません。ドナー自体の過去の学習を「データを使っていない」と意味するものではありません。数学能力が向上するかは評価結果で判断してください。

| 用途 | リポジトリ | コミットの扱い |
|---|---|---|
| 通常の元モデル | `Qwen/Qwen3.8-27B` | 初回にmainを解決して固定 |
| 数学差分の祖先 | `Qwen/Qwen3.8-27B` | `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0` |
| 数学ドナー | `baseten/math-sgd-qwen38_27b-expert` | `5d653bbde2c8aac822f430c639b37468fe438208` |

調査時のmainは `37561816e66b5b9153b1b64c10968c18c1e6f4a0` でした。祖先版と18個の重みシャードのハッシュは一致しましたが、README・チャットテンプレート・tokenizer設定に差がありました。互換性の検査を無効にせず、版を合わせています。

方向除去は、検証済みの方向を格納した `.npy` を `DIRECTION_PATH` に指定して有効にします。要素は有限値・非ゼロ、形は `(hidden_size,)` が必要です。方向の数値条件を検査し、正規化した方向に対する射影と、量子化後の実行時射影を組み合わせます。任意の方向が「拒否」を表すことや、拒否率が低下することは数値検査だけでは証明できません。

この実装は固定のtriality回転バンクを使う符号化です。新しい回答を学習したり、回転を数学正答率で最適化したりする実装ではありません。

## GGUFと実行互換性

出力は **Spin8用の独自GGML型を含むGGUF** です。同梱パッチを適用したランタイムを使ってください。通常のllama.cpp、Ollama、LM Studioで読み込める標準量子化形式とは異なります。

対象行列の符号化ペイロードは128重みあたり34バイト、つまり2.125 bit/weightです。ファイル全体には非量子化テンソル、回転バンク、語彙、テンプレート等も含まれます。2.125という値をモデル全体の実効bit数や性能値と読み替えないでください。

公式変換器のQwen向けテンソル変換、線形Attentionの並べ替えと融合、語彙・テンプレート処理を利用します。出力は画像エンコーダーとMTPを除いたテキスト推論用モデルです。

## ベンチマークの仕様

既定はGSM8K testの固定64問です。全問モードでは1,319問を評価します。データセットのコミット・ファイルハッシュ・問題IDを記録し、回答は重みの編集や学習に使いません。

F16基準モデルは、取得済みの同じ祖先HFチェックポイントから公式変換器で作成します。これは元のBF16実行そのものではなく、同じGGUFランタイムを使うF16基準です。数学差分や方向除去を有効にした場合も、基準は変更前の元モデルです。

比較するモデルは順番に読み込み、同じ問題、レンダリング済みプロンプト、入力トークン、生成条件で評価します。既定はtemperature=0、生成上限2,048トークン、thinking offです。設定とプロトコルは結果に保存します。一般のリーダーボードと条件が同じとは限りません。

記録する項目は次のとおりです。

- 数値の最終回答の正答率と95% Wilson区間
- 指定の最終回答形式にも従った正答率、形式違反率、回答抽出失敗率
- F16から正解に変わった問題数、不正解に変わった問題数、問題ごとの対応結果
- 生成上限に達した件数、入力切り詰めの検出
- プロンプト処理速度・生成速度、実際のサーバー条件とGPUへの配置情報
- サーバープロセスとGPU全体のサンプリングされたVRAM使用量

未完了のthinking内の数字を最終回答として採点しません。64問の結果は小規模な確認です。全問評価や別問題集合による確認を行わずに、一般的な数学能力向上を断定できません。

GPUの自動割り当てがF16とSpin8で異なる場合、速度差にはCPUへのオフロードの差も含まれます。記録された条件での速度として扱ってください。

## 容量・再開・ログ

公式元モデルの重みファイルは約55.56GB、数学ドナーのテンソルペイロードは約53.79GBです。通常量子化では元のHF重み、圧縮済みキャッシュ、最終GGUFを保持します。数学差分ではドナー分も必要です。F16比較を有効にすると、さらに数十GBの基準GGUFが必要です。

変換前とF16基準作成前に空き容量を確認します。大きな埋め込み行列はmmapからタイル単位で読み、全体のF32コピーを作りません。他の変換テンソルには、結果配列の大きさの上限を設けています。この上限はプロセス全体のRAM使用量の保証ではありません。

HFダウンロードは同じ作業ディレクトリで再開できます。量子化は、完了したテンソルのキャッシュを検証して再利用します。実行途中の1テンソルは再計算になる場合があります。VMが削除された場合、`/content`のキャッシュは残りません。

この量子化器は研究用実装です。27B全体の所要時間・生成速度・正答率について、未実測の値を約束していません。大きなテンソルの処理中も進捗を表示し、完全なログは作業フォルダーに保存します。

設定を変える場合は、`OUTPUT_NAME`を空にして自動生成される実験名を使うか、新しい出力名を指定してください。別レシピの完成済みGGUFは自動上書きしません。

## 検証範囲

ローカルのPython 3.13環境で、HF取得・再開・破損検出、ネイティブCPUビルド、通常／射影付き推論、API生成、HF直接変換と従来変換の数値一致、実際の一連の小型モデル変換・推論を確認しました。

ユーザーのColabでは、Python 3.13.16、Torch 2.14.1+cu130、CUDA 13.0、NVIDIA A100-SXM4-80GBで小さなCUDA行列積が成功しました。この確認を、Spin8 CUDAカーネル・27B全体・GSM8K評価の完了と取り違えないよう、別の記録にしています。

最終的な実測結果は、同梱の検証記録とColab実行後の各レポートを参照してください。構文検査だけで「実機動作確認済み」と表示する処理はありません。
