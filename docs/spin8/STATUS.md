### 比較条件の修正

通常のCUDA行列積には、F32テンソルでも独自MMF経路でTF32命令を使う箇所がありました。CPU参照との比較にこの演算精度の差とF16キャッシュの丸めが混ざらないよう、数値比較時だけ次の条件を使います。

- 両モデルのK/Vキャッシュを `--cache-type f32` で揃える。
- 比較用の子プロセスに `GGML_CUDA_SPIN8_VALIDATE_F32=1` と `NVIDIA_TF32_OVERRIDE=0` を渡す。
- 通常のF32 `MUL_MAT` をcuBLAS F32へ送り、Spin8の専用カーネルはそのまま使う。
- 許容誤差は元の `atol=1e-4`、`rtol=1e-4` を維持する。

生成APIの検査にはこの比較専用環境を渡していません。実装は [CUDAディスパッチ](../../ggml/src/ggml-cuda/ggml-cuda.cu)、[ネイティブ検証](../../tools/spin8/verify_native.py)、[Colab bootstrap](../../examples/spin8-colab/payload/colab_app/bootstrap.py) にあります。比較条件は `reports/build-report.json` の `parity_precision_profile` と各 `parity.json` の `precision_environment`、`cache_type_k`、`cache_type_v` に記録します。

これらの合格は、同じSpin8重みに対する復号・演算・グラフ接続の確認です。元のBF16モデルに対する量子化品質や、数学能力、拒否挙動の評価ではありません。

## 量子化と重み編集の意味

Spin8のpayloadは128重みにつき34バイト、2.125 bits/weightです。各圧縮行列に4,608バイトのF64回転bankがあり、その他のテンソル、metadata、alignmentが加わります。最終モデルのファイルサイズを2.125 bpwだけで確定できません。

既定のtriality bankは固定seedから構成されます。量子化CLIは数学目的で回転を学習せず、三つのモデルによる推論も行いません。uniform fallbackを含むため、すべての重みが三値表現とは限りません。

一般の重み編集ツールは選択した行列に `W_target + alpha * (W_donor - W_base)` を適用します。自動HFパイプラインではtargetとbaseを同じsourceにそろえた補間になります。回答データによるSFTやoptimizer更新は行いません。形状やtokenizerの照合が通っても、ドナーによる能力移転の有効性を証明したことにはなりません。

方向射影は、指定されたモデル固有の有限な非ゼロベクトルを使う代数操作です。量子化前の重み編集と、量子化後のランタイム射影を組み合わせます。入力方向が拒否を表すかは実装が自動判定せず、数値検査だけでは意味を検証できません。既定設定では数学差分と方向射影は無効です。
